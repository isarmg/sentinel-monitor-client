# Sentinel Client 0.3.0

The first Sentinel edge Client provides a common camera model with RTSP and ONVIF adapters. It discovers ONVIF identity, capabilities, profiles, stream URIs, and PTZ support, probes real stream health, and reports only normalized data to the Server.

Interactive Setup now checks FFmpeg/FFprobe before pairing, discovers or accepts a manual camera, reads credentials without echo, selects local/Server recording, and probes the real stream before saving it. Automation keeps the protected stdin path. A camera-stage failure preserves the committed Client identity and can be resumed with the camera commands.

Camera credentials remain on the Client. Paired instances can publish live main/sub streams to the Server while recording either on the Server or in local 15-minute MP4 segments. Linux, Windows, and macOS binaries are built from the tagged source with SHA-256 checksums.

Camera configuration is reconciled while the process is running. Removing the final camera keeps the paired Client online, sends an empty snapshot, and terminates obsolete publisher and recorder processes.

Local recording coordination now runs independently of Server snapshots. A Client can start or restart local recorders while the Server is unreachable, while remote publishing and commands remain tied to successful control-plane communication.
